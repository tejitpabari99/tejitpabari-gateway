## Must-fix

1. **[Bug Hunter]** `auto-emailer/index.html:634-636` (`startSending` → `saveOrgThen(doStartSending)`) and `:374-390` (`saveOrgThen`): a regression in the send flow. The Send button now runs an async `saveOrganization` round trip before the old flow, and nothing is disabled or guarded during that wait. Before this change, `confirm()` ran synchronously on click, so it blocked a second click, and `btn.disabled = true` followed right after. Now a double-click (or an impatient second click while the save is in flight, typically 0.5-2 s) queues two saves. Each success handler calls `doStartSending`, so the user sees two "Ready to send…" confirms back to back. Clicking OK on both starts **two concurrent `sendEmailsSequentially` loops over the same rows, so recipients get duplicate real emails**. The two loops also produce two `reportBatch` calls with different `runId`s, so Worker dedupe does not catch it and the batch is double-counted. `doStartSending` has no `if (btn.disabled) return` guard. → why: duplicate emails to real recipients is user-facing harm, and the fix is one line. → fix: disable `sendBtn`/`testBtn` (or set an in-flight flag) before `google.script.run…saveOrganization`, re-enable in the failure handler, and/or add `if (btn.disabled) return;` at the top of `doStartSending`/`doSendTest`. Add a ui-org test: two `startSending()` calls before the save resolves lead to at most one `sendEmailBatch`. `[verified: traced index.html:634→376→383 onSaved(); doStartSending sets btn.disabled only after confirm at :687; no reentrancy guard]`

## Notes (non-blocking)

- **Dedupe / x_run (asked):** no legit pings get dropped. `step_failed` and test `batch_done` pass `{}` extras, so each gets a fresh server `randomChars_(12)` run id (`code.gs:120`). Several `step_failed` events in one session therefore never collide. Only `reportBatch` carries the client `runId`, which is made once per loop (`index.html:728`), and `reportOnce` sends it at most once per loop. `newRunId()` output (16 chars of `[a-z0-9]`) matches both the script regex `^[a-z0-9]{8,32}$` and the Worker charset `[a-z0-9_-]{≤40}`. `[verified: grep logUsage_ calls code.gs:197,236,257,327,700,929,934,1098,1115]`
- **PII firewall:** good. `org` and `uid` come from props. Fields are allowlisted, and extras accept only `x_` keys with numeric, boolean or token values. Error text only reaches `classifyReason_`. The catch logs a fixed string. Pre-existing `console.error(error.message)` lines are unchanged, and the guide already says logs can hold Google error text. `[verified: code.gs:76-127; test usage-ping.test.js:128,326]`
- **XSS via org:** none. The org is only assigned via `.value` (`index.html:362,383`) and is never put into innerHTML. Server errors are static strings. `[verified: grep orgName index.html]`
- **Ping failures:** these never surface to the user. Everything sits inside a try/catch with `muteHttpExceptions`, and the client `reportBatch` has no handlers. Accepted and deferred: UrlFetchApp has no timeout, so a hung endpoint delays the test or failure response (PRD Risks).
- **Counts:** skipped rows are excluded via `reportOk`. `n=ok+fail` is clamped again in `logUsage_`, so `ok=5000, fail=10` gives `n=5000`. That is consistent with the Worker cap and harmless. A batch with zero eligible rows reports `n=0` (prod `batch_done`), which counts the org as "active". This is arguably correct, since the user ran a batch.
- **Guide privacy list** (`INSTALLATION_GUIDE.md:272`) leaves out "failing step", "run code" and "which app sent it", although PRIVACY.md lists them. The guide links to PRIVACY.md, so this is not misleading, but you could add the items if you want it exhaustive.
- **`saveOrganization`** collapses whitespace *before* it strips control chars, so `"a \u0001 b"` is stored as `"a  b"`. This is cosmetic, because the Worker re-normalizes.
- Existing positional `google.script.run` args are unchanged (`sendTestEmail`, `sendEmailBatch`, `sendSingleEmail`). The tests were updated only to account for the extra leading `saveOrganization` call. `[verified: ui-tabs.test.js diff]`
